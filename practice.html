企业 AI 提效地图（新手先看）

企业提效 = 把重复脑力活交给模型，把决策与责任留在人；工具选型看「数据在哪、谁能审」。

  • 个人层：写提示、改稿、总结会议、写代码草稿。

如何用飞书 AI 生态提效

飞书把「文档 / 表格 / 会议 / 知识 / 智能体」放在同一工作台——AI 提效优先从「数据已经在飞书里」的场景开始。

  • 智能伙伴 / aily：团队可定制业务智能体（答疑、报销助手等），可关联知识、操作文档与表格（以飞书当期产品能力为准）。
  • 多维表格：零代码业务表 + AI 字段、AI 生成工作流、仪表盘；可作轻量「业务系统」。
  • 开放平台：用 API 把多维表格当数据层，对接自研前端或 AI Coding 项目。
官方 飞书官网 多维表格产品页 飞书开放平台 智能创建/编辑多维表格说明

新手实操路径 A：知识问答（本周可试）

  1. 把制度、FAQ、产品手册放进飞书云文档/知识库，结构尽量清晰（一主题一文档）。
  2. 开通团队可用的智能问答/智能伙伴能力（以企业管理员开通范围为准）。
  3. 在群里约定：「先问飞书知识，再 @ 人」；要求回答带来源文档链接。
  4. 每周收集答错题 → 补文档（这就是企业级 RAG 的「知识运营」）。

新手实操路径 B：多维表格 + AI 搭轻量系统

一张表 = 半个业务系统：字段存数据，视图给人看，自动化/AI 节点替人跑腿。

  • 选一个痛点：请假台账、客户线索、内容排期、采购登记——只做一个。
  • 先设计字段（状态、负责人、截止日期），再让 AI 生成公式/分析（产品内能力以官网为准）。
  • 需要「像应用一样用」时，关注多维表格的应用模式/仪表盘能力（飞书产品更新见官方公告）。
  • 复杂流程：用 AI 生成工作流或自动化，关键步骤加人工节点。
多维表格 应用模式相关介绍

新手实操路径 C：自定义智能体（团队数字员工）

  • 选一个窄角色：如「报销政策答疑」「周报收集助手」——越窄越稳。
  • 绑定知识范围；写清系统提示：能做什么、不能做什么、何时转人工。
  • 在群内灰度 1–2 周，收集失败案例，改提示与知识。
  • 涉及写表、发消息等动作：必须权限最小化 + 管理员审计。

路径 D：多维表格当「后端」+ AI Coding 做前端

常见组合：用多维表格存业务数据，用开放平台 API 读写；前端用 AI Coding 快速生成页面。 飞书官方内容也讨论过「用多维表格做数据层/管理后台」的思路。

AI Coding 实操 1

如何用 AI Coding 打造一个网站

别一上来「帮我做一个完整网站」。先写清一页需求 → 静态可打开 → 再迭代一页功能。

  • 工具：Cursor、Claude Code、Codex CLI、GitHub Copilot 等（任选其一起步）。
  • 关键文件：项目说明（如 README / CLAUDE.md / Cursor Rules）写清技术栈与禁止事项。
  • 原则：小步提交、你看懂再合并；AI 写的代码你要能解释。
实践参考 Vibe Coding 最佳实践 Cursor Rules Claude Code 文档

推荐步骤（静态官网 / 知识站 / 落地页）

1
写「一页 PRD」
目标用户、3 个页面、主色、必须有的模块（Hero、目录、页脚）。不要一次写 20 页。
2
定技术栈（新手推荐）
纯 HTML/CSS/JS 静态站（本知识库即是）；或 Vite + 简单框架。先求「能打开」，再求框架。
3
让 AI 搭骨架
提示示例：「根据 PRD 生成 index.html + styles.css，响应式，左侧目录，不要引入未说明的依赖。」
4
本地预览与验收
用浏览器打开或 python -m http.server。对照 PRD 勾选：导航、移动端、死链。
5
一次只加一个功能
例如「只加搜索框」或「只加一节内容」。大而全的一次生成最容易翻车（社区对 vibe coding 的常见忠告）。
6
发布
GitHub Pages、对象存储静态托管、或公司现有站点。注意不要把密钥写进前端。

可复制提示词模板（建站）

你是前端工程师。根据下列 PRD 生成可直接打开的静态网站。 约束：仅用 HTML/CSS/JS；中文；移动端可用；不要编造外部 API Key。 PRD：【粘贴你的一页需求】 先输出文件列表，再逐文件给出完整代码。

AI Coding 实操 2

如何用 AI Coding 做应用（小工具 / 内部系统）

应用 = 界面 + 数据 + 权限。新手优先「前端 AI 生成 + 飞书多维表格/表格当数据」，少碰复杂服务器。

  • 最小应用：表单提交 → 列表展示 → 状态修改。
  • 数据放哪：飞书多维表格 / 云文档统计；或本地 JSON（仅演示）。
  • 权限：谁可读、谁可写，必须在第一天想清楚。

推荐架构（企业友好）

界面层

AI Coding 生成 Web 页面（查询、表单、看板）

↓

业务逻辑

少而清晰的 JS/服务函数；复杂规则写进文档再让 AI 实现

↓

数据层

飞书多维表格 / 企业数据库（API 读写）

↓

身份与审计

飞书登录/企业 SSO；操作日志；密钥只放服务端

分步实操（示例：团队「需求收集小应用」）

  1. 在多维表格建表：标题、描述、优先级、状态、提交人。
  2. 在开放平台创建应用，开通多维表格权限，拿到凭证（勿提交到 Git）。
  3. 用 AI Coding 生成：列表页 + 新建页；接口层单独一个 api.js。
  4. 先只做「读取列表」跑通，再做「新建」。
  5. 加状态流转与简单筛选；关键操作写操作日志字段。
  6. 找 2 个真实用户试用一天，根据吐槽改提示词与字段。

实操避坑（社区共识摘要）

① 先设计再生成，不要「一句话做完整 App」。 ② 用规则文件（Cursor Rules / CLAUDE.md / AGENTS.md）固定技术栈与代码风格。 ③ 安全相关规则单独写清（密钥、鉴权、输入校验）。 ④ 你看不懂的代码不要上生产。

治理：让提效可长期跑

1
数据分级
公开 / 内部 / 机密。机密默认不上公有模型；用企业批准通道。
2
人在回路
对外邮件、合同、财务、人事结论必须人点确认。
3
提示与技能资产化
把好用的提示/Skill 收进团队知识库，版本管理，像代码一样评审。
4
效果度量
记：节省时长、错误率、用户满意度。没有度量的提效容易变成玩具。
