# 企业提效页排版自查 · 2026-07-22

## 审计范围

- 页面：`practice.html#cli-loops`
- 用户目标：在很短时间内看懂一个企业问题如何经过 AI 和飞书形成可确认的工作闭环
- 设备：桌面 1440 × 1000、参考宽度 576 × 713、手机 390 × 844
- 证据目录：`C:/Users/Lay/.codex/visualizations/2026/07/22/practice-layout-audit/`

## 步骤与健康度

1. **进入企业提效页 — 健康。** 页面保持八站知识路线，顶部目录已从十个混合入口收敛成八个站点。
2. **定位“做出价值” — 健康。** 标题、核心结论、四步图例和问题筛选依次出现，阅读入口明确。
3. **扫读一个业务闭环 — 健康。** 每张卡先说问题和收益，再用“输入 / AI / 飞书产出”呈现信息流，最后单列人工确认。
4. **按问题筛选 — 健康。** 会议筛选被设置为按下状态，桌面弱化其他卡片，手机隐藏其他卡片，减少注意力竞争。
5. **展开并复制 AI 指令 — 健康。** 指令默认收起；展开后复制按钮进入“已复制”状态。

## 已确认的优点

- 知识仍处在完整主线中，没有把场景拆成零散技巧。
- 视觉语言沿用第三版水彩调性，且没有新增 SVG 内容图。
- 默认页面只呈现理解任务所需的信息，完整提示词按需出现。
- 390px 下页面宽度未超过视口，内容图片完整显示。

## 本轮发现并修复的高影响问题

1. **结构性样式失效：** 媒体查询漏括号，导致桌面/平板卡片样式不生效。
2. **信息同权：** 场景、价值、步骤、确认和提示词全部处在同一视觉层级。
3. **工作流不可见：** 原有五个动作只是连续文字，用户看不出“AI 在哪里做了什么”。
4. **导航职责混乱：** 本页目录中混入跨页面专题链接，增加扫描负担。
5. **移动端断行缺陷：** 确认语中的强调词和标点被拆散。

## 仍值得继续改进的地方

- 全站还有一些页面使用相似的长段落结构，需要逐页用同一规则检查，而不是只修这一页。
- 当前问题筛选依赖用户主动点选；下一步可以根据入口来源预选场景，例如从“会议”知识页进入时默认只展示会议闭环。
- 手机端顶部站点导航可增加可滚动提示，但不应新增常驻说明文字。
- 截图只能确认可见层级、重排和明显对比风险；完整键盘路径、屏幕阅读器朗读和 200% 缩放仍需专门的无障碍测试。
